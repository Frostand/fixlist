## Post-hoc binding

`scan/venv-python scan/bind_scene_identity.py <run-dir> [--write]` defaults to
read-only JSON inspection. It requires a completed run, valid unbound v1/v2
suggestions, valid decoded scene/count/metadata, ordinary contained frames for
all keyframe/bestFrame/perFrame references, and scene/frame mtimes no later than
original inference createdAt. Reads use anchored directory descriptors and
O_NOFOLLOW for each ancestor/leaf, with stable size/mtime/ctime checks.

Identity hashes actual scene/keyframe/alignment/run/script bytes. Processing
provenance distinctly says post-hoc; model identity is null. This associates
surviving present-day files under the specified conservative checks. Mtime is
mutable and does not prove inference-time bytes or authentic history. No model
weight, accuracy, geometry or home-safety attestation is made.

Explicit `--write` rechecks every source snapshot, exclusively preserves the
original exact bytes in a UTC-named backup, fsyncs the result and atomically
replaces suggestions.json. Existing backups and already-bound files are refused.
Synthetic tests cover v1/v2 success, mismatched count, missing frames, symlinked
frame/parent, newer scene/frame, incomplete run, already-bound input, backup
collision, replace failure and a source changed after inspection. The TypeScript
integration test accepts actual Python-bound synthetic output for its matching
scene and rejects a different equal-count scene.

## Exact npm workflow

Only package.json scripts changed; dependencies and lockfile were untouched:

```json
"ios:sync": "npm run build && cap sync ios",
"ios:demo": "npm run ios:demo:stage && npm run ios:sync && npm run ios:demo:install",
"ios:demo:stage": "node scripts/ios-demo-scan.mjs --stage ios/DerivedData/fixlist-demo-scan-stage viennese-v2",
"ios:demo:install": "node scripts/ios-demo-scan.mjs --install-staged ios/DerivedData/fixlist-demo-scan-stage"
```

Stage mode validates the original complete bundle before build/sync and writes
only to the existing ignored ios/DerivedData cache. A malformed/missing scan
short-circuits before Capacitor touches native web assets. The stage contains
all copied bytes, exact app index, and a SHA-256/size manifest. Install mode
uses only those staged bytes, not potentially changed captures, and rechecks
all hashes, exact file membership and app validators before atomic installation.
Unrelated stage-path directories are not replaced. A known prior valid stage is
replaced only after the new one validates. Symlinks, extra files, altered bytes,
and an invalid bundle with a rewritten manifest are rejected before installation.

Tests simulate cap sync removing/recreating the native web-assets directory,
remove the original capture directory, and successfully install the original
staged snapshot afterwards. Other tests cover invalid staging preserving the
old bundle/stage, staged snapshot replacement, tamper rejection, private-path
restrictions, unrelated-directory preservation and exact npm ordering. The old
one-command bundleScans API remains covered by its original regression tests.

**Non-atomic remainder:** cap sync itself still deletes/replaces the complete
native web directory. The whole build/sync/install sequence is not a transaction.
A sync failure can leave partial native web assets; interruption after sync can
leave the app temporarily without local-scans. The validated stage remains for
recovery after a successful sync, using `npm run ios:demo:install`. No actual
owner native assets were modified by this worker.
