# On-device relevance pilot — 2026-10-23

Chosen model: **ViT-B-32**. Best MobileCLIP minus MIT ViT-B-32 pooled held-out AUROC = 0.019186; the predeclared permissive-license preference applies within 0.03.

## Protocol and limits

125 photos with GPT-6 Luna boolean labels, not expert ground truth. Relevance only: these numbers do not measure hazard identification, home safety, or physical-device performance. Condition positives are insufficient; no condition classifier is fitted or shipped.

Fixed seed-7 split from `scan/calibration.json`: 102 development photos, 23 held-out photos, 33 development groups and 15 held-out groups. Group membership is preserved exactly, including sources with multiple images. No image or group crosses the split.

Prompts in `prompts-source.json` were frozen before scoring. Positive prompt cosine is averaged; shared neutral prompt cosine is averaged; raw relevance = sigmoid(model logit scale × (positive mean − neutral mean)). Full image plus nine row-major crops, each 60% of image width and height with origins at 0%, 20%, 40%. Each view uses the model’s resize-shorter-side, centre-crop and normalization. Deployment uses the maximum over all ten views; full-only is reported as a fixed ablation, not selected using held-out outcomes.

Per-item thresholds maximize development recall at precision ≥ 0.8 with at least two development true positives; ties prefer higher precision then higher threshold. A threshold of 1.0 means abstain. Held-out precision was measured once at those thresholds and never used to retune. Sparse per-item held-out counts do not establish stable precision. Pooled metrics treat each image-item pair as an observation; source correlation limits generalization. AUPRC is average precision, with undefined values reported rather than replaced by zero.

Calibration candidates reuse grouped five-fold development selection and the existing paired 1,000-group-bootstrap adoption rule (held-out Brier improves, upper paired-difference CI < 0, AUROC drop ≤ 0.02). Calibration is **not shipped** in this bounded pilot even when the rule passes; raw relevance scores and development thresholds are retained. Existing Mac condition calibration is never transferred.

The model comparison uses the held-out results by explicit task requirement, so these data are consumed for model selection. A future independent test set is required for an unbiased estimate of the chosen model’s generalization.

## Core ML parity

20 deterministic, evenly spaced manifest photos (not selected by score): minimum cosine **0.999988249**, mean **0.999992636**; all ≥ 0.99: **True**. Mixed-precision image encoder: large linear weights/operations FP16; patch convolution and other math FP32, model-owned normalization, exact Pillow-preprocessed RGB image input. Core ML configured with compute units `.all`. macOS single-image prediction median 0.040276s; p95 0.087940s. These exclude JPEG decoding/cropping and do not predict iPhone latency. Package 172.37 MiB. torch 2.14.1, coremltools 9.0.

Package SHA-256 tree: `d34f21f23310ad8807ee51701896385a673f92669fbe86d9ffa4eff70fdcafa2`. Weights SHA-256: `ac4f8c4b88af6d963118cbf40ad93176d092abbedfcb752601ae1866352656e6`.

A fully FP16 conversion failed the fixed gate (minimum cosine 0.981683249). Keeping normalization/attention in FP32 alone did not resolve it. Layer tracing found error before the first transformer block; keeping the patch convolution FP32 resolved it. The passed artifact keeps the large linear weights FP16. A full FP32 diagnostic matched the failing image at cosine 1.0 on CPU but failed to create an `.all` execution plan; it is not shipped. Failed diagnostic artifacts remain private in `.cache/`. Core ML predictions completed despite nonfatal teardown cache-write warnings denied by the sandbox.

The actual Swift JPEG-to-ten-view-score path on 20 fixed eval photos: max raw score difference 0.095896915, mean 0.010565443; 0 of 160 threshold decisions differ from PyTorch. Native macOS median 0.291243s and p95 0.449306s per photo, including preprocessing and inference. These are host measurements, not iPhone latency or physical-device validation.
