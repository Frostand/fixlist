# FixList roles UI implementation plan

**Goal:** A local, phone-first, translated resident/helper/volunteer journey consuming the existing role domain API.

**Architecture:** Small typed hash routes and one application controller dispatch actor-carrying commands. Resident screens consume capability-limited household projections; volunteer screens accept only volunteer projections and public identity labels. Dictionaries own authored copy, catalog translations use stable IDs, and photo operations compensate on storage failure.

**Constraints:** No dependency or domain-rule changes; no edits to scan/, ios/, package/lockfile or Capacitor config; no commit. Existing tokens, Atkinson typography, native print, local-only storage, explicit confirmation and granular sharing remain binding. Parent owns acceptance.
